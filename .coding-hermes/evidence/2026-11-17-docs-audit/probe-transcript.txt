===== E. specs/cli.md pinned source line numbers vs the shipped wrapper =====

$ grep -n standalone/terminal-jail:255\|line 1008\|standalone/terminal-jail:326-346\|seccomp.py:57 specs/cli.md
215:- `--seccomp`: the launch becomes `unshare <flags> bash -c 'exec python3 "$@"' terminal-jail <seccomp-loader.py> <command> [args...]`. The loader applies the BPF filter inside the PID namespace, then `exec`s the payload. This launch path is reached only via the `--seccomp` flag (`USE_SECCOMP=1`, `standalone/terminal-jail:255`); the wrapper then exports `TERMINAL_JAIL_SECCOMP=1` (line 1008) as the loader's own enablement handoff, and `seccomp_enabled_from_environment()` (`plugin/terminal_jail/seccomp.py:57`, truthy set `1`/`true`/`yes`/`on`, everything else disabled) consumes it. Setting `TERMINAL_JAIL_SECCOMP=1` without the flag does not route the payload through the loader and does not apply any filter (verified live: `Seccomp: 0` in `/proc/self/status` inside the jail). An explicit `TERMINAL_JAIL_SECCOMP=0` does not veto the flag (verified live: `Seccomp: 2` with `--seccomp` and the env var at `0`). The loader path is resolved relative to the wrapper (`standalone/seccomp-loader.py`); a missing loader is a preflight error (exit `2`).
216:- Interruptor evaluation (`--interruptor`, default on): before preflight/launch, the reconstructed command string is piped to `plugin/terminal_jail/interruptor_bridge.py` (located next to the wrapper, or via the Python module path). The bridge returns JSON: `{"action":"block",...}` → the wrapper prints a formatted block box to stderr and exits `126` (in `warn` mode it prints `[terminal-jail] WARN: ...` to stderr and allows execution); `{"action":"modify","modified":"<unshare-prefixed rewrite>"}` → the rewrite already contains its own `unshare` prefix and is executed as-is via `bash -c` (no second wrapping — double `unshare` fails with EPERM); the wrapper's namespace preflight describes its **own** launch and never the rewrite, so when a rewrite is present the probe runs with the **rewrite's own** flags (`unshare <flags> true`, taken from the rewrite's `<prefix> bash -c <payload>` shape) — a host that denies bare-mode namespaces while permitting `unshare --user` therefore still runs the rewrite, and only a rewrite whose own prefix cannot be created exits `2` with an `auto-sandbox modify unavailable` verdict (never the generic namespace-creation message, DF-TERMINAL-JAIL-11) — except under composed mode (next subsection), where the rewrite's payload runs without its namespace prefix instead of refusing; a rewrite that carries no `unshare` prefix adds no namespace at this layer and is executed as-is; `{"action":"allow"}` → normal launch. If the bridge is unavailable — not found, or exiting nonzero — the wrapper FAILS CLOSED in the default `enforce` mode: it prints the `COMMAND BLOCKED — interruptor-bridge-unavailable` block box to stderr and exits `126` with the payload never executed (`standalone/terminal-jail:326-346`; verified live with `TERMINAL_JAIL_BRIDGE=<missing path>` and with a bridge that exits nonzero). In `TERMINAL_JAIL_INTERRUPTOR_MODE=warn` the wrapper instead prints `terminal-jail: WARNING — interruptor bridge not available; running without firewall (warn mode)` to stderr and lets the command run unguarded (verified live: payload ran, exit `0`). `--no-interruptor` and `TERMINAL_JAIL_INTERRUPTOR_MODE=disabled` skip evaluation entirely.
[exit=0]
